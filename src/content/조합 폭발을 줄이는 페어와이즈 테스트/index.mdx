## 페어와이즈 테스트란?

페어와이즈 테스트는 모든 조합을 테스트하는 대신, 파라미터들의 **모든 짝(pair)이 최소 한 번씩 조합되도록** 테스트 케이스를 생성하는 테스트 설계 기법이다.

대부분의 소프트웨어 버그는 1~2개의 변수 상호작용으로 발생한다는 연구가 있다.
NIST 자료에 따르면 브라우저 도메인에서 2-way 조합만으로도 약 85%의 결함이 검출된다.
그래서 모든 조합을 다 테스트하기보다, 페어와이즈로 효율적으로 커버해 테스트 비용을 줄일 수 있다.

![[출처] NIST](./nist-2way-coverage.png)

## 언제 쓰면 좋을까

여러 파라미터가 있어 조합이 폭발할 때 쓰기 좋다.

예를 들어 파라미터 3개에 각각 값이 3개씩 있다면 3 × 3 × 3 = 27가지 조합이 나온다.
이걸 전부 테스트하기는 현실적으로 어렵다. 페어와이즈를 쓰면 9개의 테스트 케이스로 모든 2-way 조합을 검증할 수 있다.

```
x: a, b, c
y: q, w, e
z: 1, 2, 3
```

## 도구와 알고리즘

대표적으로 이런 도구가 있다.

- **PICT**: MS가 개발한 오픈소스 툴
- **[pairwise.yuuniworks.com](https://pairwise.yuuniworks.com/)**: 웹 기반 2-way 생성기
- **ACTS**: NIST가 개발한 무료 라이센스 t-way 툴

도구마다 사용하는 알고리즘이 조금씩 다르다. 여기서는 PICT가 사용하는 GCD라는 그리디 알고리즘을 기준으로 살펴본다.

## PICT는 어떻게 테스트 케이스를 만들까

GCD 알고리즘은 단순하다. 각 단계마다 **아직 테스트하지 않은 조합을 가장 많이 포함하는 값**을 우선 선택해 테스트 케이스를 만든다.

예를 들어 이런 파라미터가 있다고 하자.

```
X: x, y
Q: q, w
A: a, b, c
```

먼저 `(x, q, a)`라는 조합을 만들면, 커버해야 할 쌍 중 아래 항목들이 채워진다.

<table>
<tr><th>페어</th><th>커버 여부</th></tr>
<tr><td>X-Q</td><td><del>(x,q)</del>, (x,w), (y,q), (y,w)</td></tr>
<tr><td>Q-A</td><td><del>(q,a)</del>, (q,b), (q,c), (w,a), (w,b), (w,c)</td></tr>
<tr><td>X-A</td><td><del>(x,a)</del>, (x,b), (x,c), (y,a), (y,b), (y,c)</td></tr>
</table>

다음 조합으로 `(x, w, ?)`까지 만들었다고 하자. 마지막 값에 따라 새로 커버되는 조합 수가 달라진다.

- `a` 선택: 신규 조합 1개 — (x,a)는 이미 커버됐으므로 (w,a)만
- `b` 선택: 신규 조합 2개 — (x,b), (w,b)
- `c` 선택: 신규 조합 2개 — (x,c), (w,c)

따라서 더 많은 새 조합을 만드는 `b` 또는 `c`를 선택한다.
이 과정을 반복하면 적은 수의 테스트 케이스만으로 모든 2-way 조합을 커버할 수 있다.

## 마무리

페어와이즈 테스트는 모든 조합을 검증하지 않고, 2-way 상호작용을 효율적으로 커버하는 테스트 설계 기법이다.
회원 등급, 결제 수단, 쿠폰처럼 조합이 많은 기능에 활용하면 테스트 케이스 수를 줄이면서도 높은 결함 검출 효과를 얻을 수 있다.
